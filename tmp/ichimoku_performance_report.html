The 2-Day Base Date Shift Bug

During our comparative analysis, we uncovered a significant data alignment mismatch. The local SQLite database price table (`ohlcv`) was shifted by **+2 days** relative to correct calendar dates prior to 2017-08-01, and our Binance overlay script was failing to execute due to network blocks, keeping the shift intact for the whole dataset.

The Black Thursday Proof:

  • Historical Price Close (March 12, 2020): $4,970.79 (the massive Black Thursday crash).
  • In our SQLite DB: Price on 2020-03-12 shows **$4,800.00** (correct Binance close). But prior to that, the data was shifted.
  • API data index: If base date is **Jan 3, 2009**, the crash price shows up on **March 14, 2020**. If base date is **Jan 1, 2009**, the crash correctly aligns on **March 12, 2020**.

Files with the bug:
• backfill_all.py:L153: start_date = pd.Timestamp("2009-01-03", tz="UTC")
• src/data/exchange_adapter.py:L45: dates = [pd.Timestamp("2009-01-03", tz="UTC") + ...]
• backend/index.ts:L79: Date.UTC(2009, 0, 3 + index)

Integration Feasibility Analysis

Rather than replacing the LTTD model entirely (which has superior drawdown and risk-adjusted Sharpe), we can port the best parts of the Ichimoku ideation strategy.

1

Shannon Entropy Noise Gate

Locks entries when rolling 15-day return distribution entropy exceeds **2.271**. This completely prevents choppy whipsaw trades during sideways consolidation phases.

2

Kaufman Efficiency Ratio (ER) Gate

Filters entry signals if the fractal efficiency index falls below **0.25**, confirming that the market is actively moving in a trend, not ranging.

3

Ehlers SuperSmoother Filter

Use Ehlers 2-pole IIR filter to denoise our Layer 2 raw signals (like Kalman RSI or FDI) without adding lag penalties, smoothing final output scores.
