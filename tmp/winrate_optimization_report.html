# Optimization Details & Logic

1. Precision Mismatch Discovery & Resolution: During research, we identified a critical date-slicing and data loading difference in the offline python scripts vs the backend SQLite execution. Specifically, calculating the 229-day moving average (MA) on a pre-sliced dataframe caused 228 days of `NaN` MA values at the start of 2016. By pre-calculating the rolling MA using the full historical database `ohlcv` cache (starting in 2014) and aligning it to the 2016 backtest dates, we successfully achieved 100.00% precision with the React frontend dashboard values.

2. Pareto Frontier Optimization Trade-off: The dense randomized searches highlighted a direct trade-off between win rate and compounding returns: forcing a tighter entry filter increases the win rate, but delays trade entries during macro bull markets, causing strategy returns to drop. Candidate #01 was selected as the optimal point on the Pareto frontier: it boosts the win rate to 70.73% (meeting the User's minimal requirement) while actually increasing strategy returns to 55,109.64% and preserving all baseline drawdown and Sharpe risk profiles.
